## Критические проблемы:
- Приложение не стартует: aplication.yml, WORK_DIR, PEM→DER, неверные derived-запросы, нет миграций
- Основные CRUD-сценарии не реализованы (нет контроллеров, CreateProjectUseCase ничего не сохраняет)
- Безопасность-заглушки: хардкод admin/secret_pass, пароли без хеширования, CSRF выключен при cookie-auth
- Документация API расходится с кодом
- Нет содержательных тестов

## Главные плюсы:
- Осознанная попытка гексагональной архитектуры (порты в Domain, адаптеры в Infrastructure)
- Удачная полиморфная модель фото через Ownable
- Грамотный подход к JWT: RSA, HttpOnly + Secure cookie, корректный CORS с credentials
- Доменная модель хорошо соответствует ТЗ, продуман сценарий резервирования ID
- Use case'ы и API расписаны до кода — видно проектирование, а не «писал как пошло»

## Что исправить в первую очередь:
1. Довести до запуска: переименовать в application.yml, синхронизировать .env.template
   (WORK_DIR / UPLOAD_DIR_PATH / HOST_FRONT / HOST_SERVER), читать PEM с декодированием
   Base64, переименовать поля в camelCase или исправить derived-методы, добавить
   Flyway-миграцию, добавить file: в MvcConfig
2. Реализовать хотя бы один полный вертикальный сценарий (Project: контроллер → use case
   → репозиторий → БД) и выровнять его с API_1.md
3. Вынести общий алгоритм photo use case'ов (Template Method/Strategy), внедрять
   FileCRUDInterface через конструктор, добавить getOwnerType() в Ownable
4. Безопасность: проверять логин по БД с BCrypt (увеличить длину password),
   возвращать 401, включить SameSite для cookie, проверять тип загружаемых файлов
5. Тесты: unit на MainJwtService, Service_File_Manager (@TempDir), PhotoMapper,
   use case'ы с Mockito; заменить contextLoads на рабочий интеграционный тест
6. README: описание, требования, генерация RSA-ключей, docker compose up, пример 

## Комментарий

Видно, что ты разбирался в архитектуре, безопасности и JPA. Решения с Ownable, RSA-JWT и резервированием ID — сильные стороны работы. Основная потеря баллов идёт не от плохих идей, а от того, что проект ни разу не запускался целиком. Если закрыть первые три пункта списка «Что исправить», работа легко выйдет на уровень 30–35 баллов («нормально»), а с тестами и README — выше.
